حاسبة أسعار تحاليل مع إرسال واتساب مباشر للعميل.

## التشغيل
```bash
pip install -r requirements.txt
python3 test_price_utils.py     # لازم يعدّي قبل أي رفع
streamlit run Invoice.py
```

## قواعد التحقق
- **اسم التحليل**: exact → alias → مصطلح غامض → قريب → مش موجود.
  أي حاجة غير `exact` أو `alias` **لازم تأكيد يدوي** — البرنامج مش بيخمّن.
- **مصطلحات محجوبة من التخمين**: PSA, H.pylori, RF, HBs, HCV, HIV, Cortisol —
  كل واحد ليه أكتر من صورة بسعر مختلف.
- **رقم الموبايل**: 010/011/012/015 بس، وبيتحول لـ `20XXXXXXXXXX` للواتساب.
- **الاسم**: مفيش أرقام، 3 حروف على الأقل، تحذير لو عربي (الـ PDF إنجليزي).

## الباقات (Profiles)
4 باقات بتتدمج في قائمة الأسعار وقت التحميل، فبتظهر في الـ search
كأنها تحاليل عادية:

| الباقة | السعر | مفرّق | التوفير |
|---|---|---|---|
| Lipid Profile | 700 | 950 | 250 |
| Liver Profile | 850 | 1,170 | 320 |
| Kidney Profile | 850 | 1,150 | 300 |
| Thyroid Profile | 870 | 870 | 0 |

بتتلاقى بالعربي والإنجليزي: `lipid` / `lft` / `tft` / `كبد` / `وظائف كلى` /
`الغدة الدرقية` — وكمان الـ typo القديم `thyroid profie`.

**حماية من الدفع مرتين:** لو الباقة في الفاتورة والموظف ضاف مكوّن منها،
البرنامج بيقف ويقول كام العميل كان هيدفع زيادة. والعكس: لو المفرّق موجود
وضاف الباقة، بيعرض يستبدلهم ويحسب التوفير.

**التعديل:** غيّر `price` في `bundles.py` وشغّل الاختبار. الملف ده منفصل
عن `labs_price_list.py` عمداً — عشان إعادة توليد قائمة الأسعار ماتمسحهوش.

## تحديث — أغسطس 2026

### Quick Panels
- ٥ panels جديدة: `ALT + AST` · `Urea + Creat` · `Uric Acid` · `HbA1c only` ·
  `HBs + HCV + HIV`. (`TSH Only` و`Urine`/`Stool Examination` كانوا موجودين)
- `Coagulation (PT+PTT)` بقى `PT + PTT`
- العرض بقى **٢ في السطر** بشبكة حقيقية، مع CSS بيمنع Streamlit إنه
  يفرد كل زرار على سطر لوحده على الموبايل

### حماية الدفع مرتين — اتوسّعت
كل الإضافات الجماعية (panels + اللصق) بتعدّي دلوقتي على `add_many()`:
- **covered** (تحليل داخل في باقة موجودة) → يتخطى + تقرير بالمبلغ المتوفّر
- **supersedes** (باقة بتغطي مفرّق موجود) → يتأجّل للبوابة اليدوية،
  عشان ده قرار فيه فلوس ماينفعش يتاخد جماعي
- الباقات بتتضاف **الأول** عشان مكوّناتها في نفس القائمة تتمسك
- dedupe: سطرين بيوصّلوا لنفس التحليل بيتحسبوا مرة واحدة

### لصق قائمة تحاليل (Copy/Paste)
`parse_bulk_tests()` بتقرا رسالة عميل زي ما هي وتقسمها ٣ مجموعات:
مؤكد / محتاج تحديد / مش لاقيله مقابل. مش بتقسم على «و» عن قصد.
اتضاف ~٧٠ مصطلح عربي دارج لـ `ALIASES`، والمصطلحات الخطرة
(زلال، صفراء، إنزيمات الكبد، تستوستيرون) راحت `AMBIGUOUS_TERMS`.

### العربي في الـ PDF
`arabic_pdf.py` — تشكيل الحروف + قلب الاتجاه، **بدون مكتبات جديدة**.
لو `arabic-reshaper` + `python-bidi` متثبتين بيستخدمهم، وإلا بينفّذ بنفسه.
الخط بيتلقّى من `fonts/` ← النظام ← Termux. تفاصيل في `fonts/README.md`.

### الاختبارات
`python3 test_price_utils.py` — لازم يطلع `ALL CHECKS PASSED` قبل أي رفع.

## تحديث 5 — كتالوج العروض بالأرقام
- **الفاتورة ← «📋 عروض المعمل (بالرقم)»**: اختار الرقم (أو القائمة الترحيبية) ← نص الرسالة (قابل للتعديل) ← واتساب. للعرض ذو السعر: صورة بقالب Orange + تحميل + مشاركة، وزرار **«⚡ طبّق العرض على الفاتورة»** بيضيف تحاليل العرض بنفس محرك الأسعار ويحط خصم ثابت يوصّل الإجمالي لسعر العرض بالظبط (ما بيلمسش خصم متسجّل قبل كده، وسعر العرض الرسمي ما بيطلبش كود موافقة).
- الرقم **27**: زرار «سجّل طلب إيقاف الرسائل» (بصمة الرقم، من غير تخزين الرقم).
- **Marketing Studio**: «📋 كتالوج العروض» يملا التصميم بالسعر قبل/بعد والتحاليل. لينك الخريطة في نص المنشور بقى حسب الفرع.
- **العروض ← Catalog**: كل العروض مع «مجموع القائمة» والفرق والفحص، وتصدير CSV، وتحذير لو سعر عرض مختلف عن باقة في التطبيق (Thyroid: 650 مقابل 870).
- **البيانات**: `offers_data.py` (الحالات: current / legacy / pending / service / bundles). أرقام القائمة اللي مفيش ليها تفاصيل (12، 14، 18، 31، 33–39) ظاهرة كـ «بدون تفاصيل» لحد ما تضيفها.
- **أرقام المعمل والفروع**: `brand.py` (`OFFERS_PHONE`, `WORKING_HOURS_AR`, `BRANCH_INFO`).
- **ازاي اخترنا النسخة الحالية؟** لما العرض ظهر بسعرين في الشات، قارنّا «قبل الخصم» بمجموع أسعار تحاليله في قائمتك الحالية: النسخ الأحدث بتطابق القائمة (فرق ≤ 20 ج)، والأقدم بتبعد 11–17% فاتحطت legacy.

## تحديث 6 — Customer CRM (من عرض السعر للحضور الفعلي)
كل حاجة فوق نفس نظام الأحداث (من غير قاعدة بيانات): `quote ← sent ← booked ← visited | lost ← recovery_request ← recovery_decision ← عرض جديد (parent)`.

| الفكرة | فين | ازاي |
|---|---|---|
| تسعير الروشتة + عروض مناسبة | الفاتورة ← «🎁 عروض مناسبة» | لو التحاليل بتطابق عرض: خصم فوري. لو ناقص 1–2 تحليل: «ضيف واحصل على العرض». + عروض «إدارة العروض» الشغّالة |
| مواعيد + عنوان + خريطة الفرع مع العرض | الفاتورة + Studio | حسب الفرع المختار؛ بتتعدّل من صفحة **Branches** (مش في الكود) |
| زيارة منزلية مجانية (6,000 ج · 6 أكتوبر والشيخ زايد · لحد 30/11/2026) | الفاتورة | تنبيه `FREE HOME VISIT ELIGIBLE` + تتضاف للرسالة. الشرط على **صافي التحاليل بعد الخصم**، والزيارة ميزة مش خصم. القواعد من **Offers ← Campaigns** |
| متابعة الحضور + استرجاع | **Follow-up** | Booked / Visited / Not visited. العميل اللي فات: «Request Special Discount» ← الإدارة (تبويب Approvals) توافق/ترفض/تعدّل ← عرض جديد مرتبط بالقديم ومعتمد. كل قرار باسم المعتمد والسبب |
| VIP + متابعة شهرية | **Customers** | New / Returning / Regular / VIP (يدوي أو بقواعد). قايمة شهرية، ومايتكلّمش العميل مرتين في 30 يوم |
| هدايا العملاء الجدد | **Gifts** | زيارة منزلية لعميل جديد ← «NEW CUSTOMER – WELCOME GIFT» ← الدكتور يأكّد التسليم (نوع/تكلفة/مين/تاريخ) |
| Dashboard | **Dashboard ← Customer Journey** | Total Quotes · Quoted Value · Visit Rate · Lost · Recovered · Discounts Granted · Free Visits · VIP · Gifts + مقارنة بالموظف + Audit Log |

**Studio:** اسم العميل ورقمه (الرسالة بتتكتب باسمه وواتساب بيفتح على رقمه). تبديل الفرع (دياموند/لاسيتيه) بيغيّر رقم الصورة والعنوان والخريطة، والرقم قابل للتعديل. عروض المعمل بالرقم في نفس خانة «املا من باقة أو عرض بالرقم» مع Lipid/Liver/Kidney.

**الدخول:** `staff_password` (Follow-up / Customers / Gifts) و`access_password` (الإدارة: Dashboard / Offers / Branches / الموافقات). لو الأولى مش متظبطة، كلمة سر الإدارة بتفتح كل حاجة.

**الخصوصية:** أسماء وأرقام العملاء مش بتتخزّن إلا لو `store_contacts = true` (وريبو الأحداث Private) — وبدونها متابعة VIP والاسترجاع مش هيقدروا يفتحوا واتساب.

**لسه ماتعملش:** قراءة الروشتة بـ OCR (محتاجة خدمة خارجية وتكلفة)، إرسال واتساب تلقائي (Business API)، وقاعدة بيانات علائقية — الأحداث الحالية كفاية دلوقتي.

## تحديث 7 — Smart Replies + فحص الإعدادات + توقيت القاهرة
- **💬 Replies**: 13 رد جاهز (أسعاركم غالية؟ · في معمل أرخص؟ · ممكن خصم؟ · عايز أعرف الأسعار · هفكر وأرد · مفيش وقت · عايز أحجز · السحب المنزلي · العنوان ومواعيد العمل · اعتذار عن التأخير · الاستفسار عن النتيجة · شكراً · إيقاف الرسائل). لكل رد **مختصر** و**مطوّل**، وبيتخصّص باسم العميل والفرع (عنوان/مواعيد/خريطة/رقم) والعروض (من الكتالوج أو «إدارة العروض») والزيارة المجانية. الإرسال بإيد الموظف.
- **تسجيل المحادثة من نفس الصفحة**: «سجّل الرد بس» / «⏰ متابعة بعد 24 ساعة» / «❌ فات + السبب». المتابعة **بتتمنع** لو فيه متابعة مجدولة أو اتعملت من أقل من 12 ساعة أو خلّصت 3 محاولات أو العميل موقوف.
- **تحليل الاعتراضات** في الداشبورد: كل اعتراض اتقال كام مرة، العروض المرتبطة، حضروا/فاتوا/مفتوحة، وأكتر سبب فوات. أسباب الفوات بقت: السعر · معمل تاني · مش بيرد · تأجيل لوقت تاني (+ الباقي).
- **Branches ← Links**: لينك التطبيق (`app_url`) ولينك تقييم Google ولينك فيسبوك قابلين للتعديل من البرنامج (أو secrets). **Branches ← Setup check**: بيفحص Secrets والروابط وأرقام الفروع وهل ريبو الأحداث **Private** فعلاً (عن طريق GitHub API).
- **التوقيت**: البرنامج كله على Africa/Cairo (`tzsetup.py`) — مش UTC بتاع Streamlit Cloud. تواريخ الحملات ومواعيد المتابعة بقت بتوقيت القاهرة.
- **لسه**: تشفير لينكات العروض بخوارزمية قياسية (AES-GCM) بدل البناء الحالي (HMAC-SHA256 + توقيع) — يتطلب مكتبة `cryptography`؛ قاعدة بيانات؛ حساب دخول لكل موظف.
